# x4kas - Claude Code Instructions

## Build & Check

```bash
cargo build              # compile the workspace (both binaries)
cargo fmt --all          # format (CI runs `cargo fmt --all -- --check`)
cargo clippy --all-targets -- -D warnings  # lint incl. tests (treat warnings as errors)
cargo test               # run test suite (100+ tests, all crates)
cargo run --bin x4kas -- --url ws://127.0.0.1:17110   # GUI against a node
cargo run --bin x4kas-cli -- rpc get_info             # CLI (public resolver without --url)
```

## Architecture

Monitors a Kaspa L1 node via wRPC, connecting by URL or through the public resolver. A Cargo workspace with two binaries over one shared library:

- `crates/x4kas-core` (lib `x4kas_core`): everything below the frontends: RPC, app state, controller, polling, analytics, config, formatting. No egui and no clap.
- `crates/x4kas-gui` (package `x4kas-gui`, binary `x4kas`): the egui/eframe desktop GUI.
- `crates/x4kas-cli` (binary `x4kas-cli`): headless commands that connect, print and exit. It must not depend on egui/eframe, so it builds fast and runs on servers without a display. The CLI will grow to cover most of what the GUI shows: put the data logic in core and keep only argument parsing and printing in the CLI crate.

### Threading model

- (GUI) `main` builds a tokio multi-thread `Runtime` by hand (no `#[tokio::main]`). eframe owns the **main thread**, which must stay **outside** the runtime context: `RwLock::blocking_read/blocking_write` panic inside it. `gui::run` enters the runtime only briefly to spawn background tasks, then drops the guard.
- **Shared state:** `Arc<tokio::sync::RwLock<App>>`. The GUI takes `blocking_write` once per frame; background tasks use `.write().await`.
- **Repaint:** background writers call `app.mark_dirty()`, which invokes the injected `App.repaint` hook (`ctx.request_repaint()`). The GUI also schedules a 1s repaint so clocks and uptime tick. Don't busy-repaint.
- **Commands:** the GUI never awaits. It sends `UiCommand`s (`Connect(RemoteTarget)`, `Disconnect`, `ExecuteRpc`, `LookupBlock`, `Shutdown`) over an mpsc channel to the controller task, which writes results back into `App`.
- **Connections:** exactly one active source at a time (`App.connection: ActiveConnection`): a URL or the public resolver (`RemoteTarget { url: None }`). Switching calls `Controller::stop_all` (abort polling, wait for the index writer, disconnect, save the analytics cache, `App::clear_node_data`). The chain stream (analytics incl. mining stats, and the address index) only runs with a direct node (`ActiveConnection::is_direct`: a URL), not the resolver; hashrate polling and the watchlist run with either. There is no embedded node for now.
- **Chain stream:** one VSPC v2 fetch loop per connection (`chain_stream::run`) hands each response to its sinks over bounded channels (`SINK_QUEUE`): the analytics engine task (`analytics_streaming::start_analytics_sink`) and the index writer thread (`index::task::start_writer`). A slow sink slows the fetch (backpressure); nothing is dropped. Its progress is `app.analytics.status` (the status bar's analytics chip). It starts from the index's saved position (or the analytics cache's, or the pruning point), skipped ahead to the backfill window (`StreamStart.backfill`, 24h in the GUI, `--backfill-hours` in `x4kas-cli index run`).
- **Address index:** `index/` (fjall LSM store under `~/.x4kas/index/<network>/`, `FORMAT_VERSION` bumps discard it). Addresses are interned to `u32` ids; every data keyspace is a six-hour slab (`tx_<n>`, `atx_<n>`, `btx_<n>`, `ast_<n>`, `apr_<n>`), so pruning behind the node's pruning point (`NodeState::pruning_point_timestamp_ms`) drops keyspaces and totals are sums over slabs. One atomic write batch per VSPC response; removed chain blocks are reverse-applied; already-indexed chain blocks are skipped, so replays are harmless. The writer is a blocking thread (`PollingHandles::index`, not aborted but awaited by `stop_index` so it releases the store's single-writer lock); queries (`index::query`) are synchronous and run in `spawn_blocking` from the controller (`LookupAddress`, `AddressPage`). The GUI thread never touches the store. Ingest benchmark: `cargo test -p x4kas-core --release -- --ignored --nocapture bench_ingest` (~50k tx/s with clustering, ~80k without; ~280 B/tx).
- **Watchlist:** `watch.rs`. `start_watch` subscribes `UtxosChanged` for the enabled entries of the network (`RpcManager::watch_utxos`, resubscribing on reconnect), seeds balances, polls pending mempool activity, coalesces each notification into per-address `AddressEvent`s (`net_changes`, `build_events`) and raises `Alert`s from `AlertRules` (`evaluate`: any activity, received/sent minimums, balance crossings, first activity after `idle_hours`; the idle rule measures from `WatchEntry::last_activity_ms`, which the task updates and saves). `UiCommand::WatchSet` saves `~/.x4kas/watchlist.toml` and restarts the task. Needs the node's UTXO index; otherwise `WatchPhase::Unavailable`. `WatchState::alerts_raised` counts alerts so the GUI's toasts (`gui/toasts.rs`) pick up only new ones; `unread_alerts` is the badge on the Monitoring tab, cleared when it is shown.
- **Clustering:** `index/cluster.rs`. The writer unions the input addresses of every transaction (common-input ownership) and any output whose change score (`change_scores`: fresh address, odd amount next to round ones, same address type as the inputs; only two-output shapes score high) reaches `CHANGE_THRESHOLD`, into a persistent union-find (`cl_parent`/`cl_size`/`cl_member` keyspaces, union by size, path compression). Guards (`may_union`): no union across different entity labels (`LabelBook::entity_name`: kas.fyi, kaspa.org and heuristic labels; the user's notes and `.kas` names are per address and don't count), none for L2 bridge protocols (Kasplex, Igra), none for covenant spends (a script-hash input whose redeem script introspects, `tx_inspect::redeem_script_opcodes`), and `MAX_CLUSTER` refuses runaway merges (counted in `IndexStatus::cluster_cap_hits`, shown in the index status). The writer takes the current label book before every batch (`IndexWriter::set_labels`). Membership is knowledge, not activity: it isn't slabbed and reorgs don't undo it. `query::cluster` (which names the cluster, `ClusterInfo::label`, by the strongest then most common member label: `LabelBook::name_cluster`) and `AddressProfile::cluster_size` read it.
- **Flows:** `query::flows` follows counterparties (`FLOW_TOP` per node) `hops` out from an address into a `FlowGraph`; `UiCommand::AddressFlows` merges results into `App.address.flows` (`FlowState`, which also keeps `FlowGraph::collapse_chains`: pass-through addresses (one flow in, one out, not a root) folded into one edge listing them in `FlowEdge::via`; the window's "Collapse chains" toggle picks `FlowState::shown`), drawn by `gui/flows.rs` (force layout in `FlowWindowUi`; click expands a node, right-click opens its Address Info; collapsed edges are dashed with a hop count).
- **Peel chains:** `index/peel.rs`. `peel_chain` walks single-input two-output spends by outpoint, backwards through `prev_txid` and forwards by finding the link-shaped spend of either output (only the unspent last remainder is picked by change score), up to `MAX_PEEL_LINKS`; `AddressProfile::peel_chain` (`PeelChain`: links oldest first, the address's 1-based `position`, `peeled_total`) is shown in Address Info and in `address profile`. Chains need `MIN_PEEL_LINKS` spends; an address with more than a few transactions is a wallet, not a link.
- **Export:** `index/export.rs`. CSV (hand-rolled RFC 4180, amounts in sompi and KAS, `time_utc` via `format::format_utc`) and JSON of an address's transactions (`all_transactions` pages through everything, `EXPORT_MAX_ROWS`) and of a flow graph (edges, with labels and `via`). `UiCommand::Export(ExportRequest)` writes to `export_path` under `~/.x4kas/exports/` in `spawn_blocking` and reports in `App.address.export` (`ExportStatus`, shown under the transactions table and in the flow window); the CLI prints the same text (`address txs --all --format csv`, `address flows --collapse --format csv`).
- **Labels:** `labels.rs`. `App.labels: Arc<LabelBook>` (replaced as a whole on change): user labels (`~/.x4kas/labels/user.toml`) over kas.fyi tags over the api.kaspa.org list (fetched in bulk on launch and every `REFRESH_EVERY` by `start_label_refresh`, `RETRY_AFTER` after a failure, progress in `App.label_refresh`; cached in `labels/kaspa_org.json` so the last list shows until the fetch lands; nothing is bundled with the build) over KNS `.kas` names over heuristics (`LabelSource::rank`). Heuristic labels are derived locally and never saved: the burn address of every network (`emission::burn_address`), and "Mining pool (<coinbase tag>)" for a payout address once the analytics sink has seen it mine `POOL_MIN_BLOCKS` coinbases (`MinerTally`, fed by `analytics::coinbase_miners`). A `Label` also carries kas.fyi's `link` and `categories` when known. kas.fyi (needs an API key) and KNS are per-address lookups that reveal the address, so they're opt-in (`LabelSettings`, `~/.x4kas/labels/settings.toml`; `App.label_settings`), run only on "Look up" in Address Info (`UiCommand::LookupLabelOnline`) and cached with negatives for `ONLINE_TTL` (`online_cache.json`). The GUI puts the book into egui data each frame (`widgets::set_labels`) so `widgets::address` can show a label chip after the address anywhere; a click on the chip (or "Add/Edit Address Label" in the address's right-click menu) edits the user's label in place (`widgets::request_label` → `SetLabel` from the frame loop), and the Settings page lists and maintains them.
- **Task tracking:** every background task (node polling via `create_and_start_rpc`, hashrate, the chain stream and its sinks, the watchlist, and one-off frontend requests via `PollingHandles::spawn_request` / `Controller::spawn_rpc`) is stored in `PollingHandles` so `abort_all` stops it. Never spawn an untracked task that writes `App`, or it keeps writing stale data after a switch.
- **Graceful quit:** a close request is cancelled, `Shutdown(oneshot)` is sent, a "Shutting down…" modal is shown, and the window closes once the controller signals completion (disconnected, analytics cache saved).

### Module Layout

Paths below are relative to each crate's `src/`.

**x4kas-gui**

- `main.rs`: entry point. Parses `Args` (`--url`, `--network`, `--refresh-interval-ms`), builds the runtime, calls `gui::run`.
- `gui/mod.rs`: `GuiApp` (`eframe::App`). Frame loop, top bar (brand, tab strip, terminal/help/settings buttons), bottom status bar (connection, node sync and analytics indicators with details on hover, network, DAA score colored by lag behind the DAG tip, pause), keyboard shortcuts, quit handling.
- `gui/dashboard.rs`: Dashboard tab, modeled on the Kaspalytics home page. Layout and the node-backed cards. Rows: DAG visualizer band, BlockDAG / Markets (⅔ / ⅓ via `widgets::weighted_columns`), Supply (incl. unspendable (burn address balance), block reward and next reduction) / Mining (incl. unique miners and blocks mined over the Top Miners window) / Node Info (incl. block and header counts), a thin full-width bar chart of transactions per 10 minutes over 24h (`analytics::tx_chart`, from `AnalyticsState::tx_histogram`), Transaction Summary / Mempool (⅔ / ⅓), Transaction Inspection, Fees (node fee-rate estimate | average | total accepted fees per window), Mining Share by Node Version / Top Miners, Top Senders / Top Receivers.
- `gui/analytics.rs`: the Dashboard's chain analytics cards (`pub(super)` bodies, called from `dashboard.rs`). Panels have a time window dropdown in the card header (`panel_card` hands the contents that window's `AggregatedView`; windows in `AnalyticsState::windows`, indexed by `AnalyticsPanel`). With the resolver they show a direct-node placeholder; while analytics catches up, its counts are partial, so the cards get no view (`Option<&AggregatedView>` is `None`): numbers show "—", lists "Analytics sync in progress…", and a pulsing orange `sync_dot` (the status bar's analytics color; progress on hover) sits in the header of each analytics card and of Fees.
- `gui/blockdag.rs`: the Dashboard's BlockDAG section. `band`: the DAG visualizer modeled on the Kaspalytics home page (newest DAA scores as columns, parent edges, tips highlighted, hovering pauses it, then hover/click blocks; animation state in egui memory). `stats`: the BlockDAG card (DAA/blue score, sink, pruning point, past median time | tip count, DAG width averaged over the last 60s, block interval, blue block rate). Also the Block Info window (`block_window`), shown on any tab. The node's `BlockAdded` stream only repaints while the Dashboard is active.
- `gui/monitoring.rs`: Monitoring tab (`MonitoringTab`, owned by `GuiApp`): add/search field (an address opens Address Info or joins the watchlist; text searches labels, the matches in a popup over the page), the watchlist table (balance, pending, 24h change from this session's events, last activity), and the Alerts and Activity cards. Shows the watch task's state in the card header.
- `gui/settings.rs`: the Settings page (`SettingsPage`, owned by `GuiApp`, opened by the ⚙ button; drawn in place of the active tab, with a left navigation of sections). Address Labels: Sources (the public list's count, its fetch state and a refresh button; the online lookups have no GUI settings, only `x4kas-cli labels kns on`) and Known Labels (add form, filter, every known label as label chip (`widgets::label_cell`, edits in place) / address (`widgets::address_bare`, no chip) / source ("manual" for the user's) with edit (`widgets::edit_label_cell`) and delete buttons).
- `gui/address.rs`: the Address Info window (`AddressWindowUi`, any tab; data in `App.address`): address and explorer links, online lookup (`LookupLabelOnline`), label (public shown, user's editable via `SetLabel`), balance and indexed totals, balance-history step chart, transactions (paged with `AddressPage`; CSV/JSON export buttons → `Export`), counterparties, the likely-owner cluster (size, most common member label, member sample), the peel chain it is a link of (position, each spend's peel and remainder), "Open flow graph", and the address's watch settings (name, on/off, rules → `WatchSet`).
- `gui/flows.rs`: the flow graph window (`FlowWindowUi`): the graph, the "Collapse chains" toggle and CSV/JSON export.
- `gui/toasts.rs`: alert toasts (`Toasts`, owned by `GuiApp`): new watchlist alerts bottom-right over any tab for a few seconds, dismissable, the address opening Address Info.
- `gui/mempool.rs`: Mempool tab (`egui_extras` table, click a row for the detail window).
- `gui/rpc_explorer.rs`: RPC Cmds tab (method list, argument form, Loop toggle, read-only JSON result viewer (`widgets::json_view`) with 🔍 links on block hashes that run `get_block`).
- `gui/connection.rs`: `ConnectionWindow`, opened from the status-bar connection button. Custom URL / public resolver, network, Connect/Disconnect.
- `gui/terminal.rs`: `TerminalPane`, the integrated terminal (bottom panel, toggled with Ctrl+` or the `>_` button). Runs the user's login shell (`$SHELL -l`, home dir) on a real PTY via `egui_term`; started on first open, kept alive while hidden, closed on shell exit. Focus follows clicks; while focused, app shortcuts and Esc go to the shell. Colors from `theme::terminal_palette`.
- `gui/help.rs`: help window (shortcuts).
- `gui/theme.rs`: palette constants, `apply` (monospace fonts + dark visuals, installed at startup), and status → label/color mapping.
- `gui/widgets.rs`: shared building blocks (`card` with the title set into its border and `card_with_header` for widgets after the title (returns the card rect), `weighted_columns` (a row of cards in proportional columns, stretched to equal height, wrapping onto new rows below a min width like CSS flex-wrap; `kv_columns` wraps the same way inside a card), `kv_grid`/`kv` (label/value rows, striped full width and highlighted on hover like the tables), `section_title` (also table headers), `subheader` (white headings over rows inside a card), `modal_window` (centered, closes on X/Esc), `or_dash`, `json_view` (JSON with block-hash links), `primary_button`, `status_chip`, `placeholder`, `direct_node_placeholder`, `CARD_GAP`/`CARD_GAP_X` (space between cards), `fit_label`, `wide_table` (re-exported from `analytics.rs`: a fixed-height list table whose first column fits the width), and `address`/`block_hash`: fitted value, copy icon and hover highlight; a click opens the Address Info or Block Info window, an address's right-click menu labels it or opens it in an explorer; an address with a known label (`set_labels`) gets a label chip; `copy_value` for plain text with a copy icon).

**x4kas-core**

- `app.rs`: central state, free of GUI types. `App`, `Tab` (4 tabs), `RpcExplorerState`, `DagVisualizer`, `DagSelection`, analytics state (`TimeWindow`, `AnalyticsPanel` windows), `IndexState`/`IndexStatus`, `WatchState` (list, balances, pending, events, alerts), `AddressState`/`AddressWindow`/`AddressView` (the Address Info window's data), `FlowState`, `ExportStatus`, `labels`, and `mark_dirty()`.
- `controller.rs`: the `UiCommand` enum, `RemoteTarget`, and the controller task. Owns the RPC manager, the index store and polling handles. Handles startup (`--url`, or idle with the connection window open; loads the watchlist and labels), connect/disconnect, RPC execution, address lookups and pages, watchlist and label changes, and shutdown.
- `polling.rs`: `PollingHandles` (task handles plus a `JoinSet` of one-off requests; `stop_index` awaits the writer thread), RPC creation (`create_and_start_rpc`) and hashrate polling.
- `chain_stream.rs`: the VSPC v2 fetch loop (`run`, `start_chain_stream`, `StreamStart`), shared by the GUI controller and `x4kas-cli index run`.
- `index/`: `mod.rs` (`IndexStore`: open/reset, manifest, interning, slabs, cluster keyspaces, pruning), `records.rs` (`IndexedTx` with per-output change scores, `AddrStats`, `PeerStats`, key layouts, varint `encode`/`decode`), `writer.rs` (`IndexWriter::apply`: transform, overlay of per-slab stats and peers, reorg undo, `peer_flows`, `link_owners`; synthetic response builders under `testing` for tests and the benchmark), `cluster.rs` (union-find, guards, `change_scores`), `peel.rs` (`peel_chain`), `query.rs` (`profile`, `transactions` with cursors, `transaction`, `counterparties`, `cluster`, `flows` and `FlowGraph::collapse_chains`, `balance_deltas`/`balance_curve`), `export.rs` (CSV/JSON text, export paths), `task.rs` (the writer thread and `IndexStatus` reporting).
- `watch.rs`: `Watchlist`/`WatchEntry`/`AlertRules` (`~/.x4kas/watchlist.toml`), `AddressEvent`/`Alert`, `evaluate`, `net_changes`/`build_events`, and the watch task.
- `labels.rs`: `LabelBook`, `UserLabels`, `LabelSettings`, `OnlineCache`, `fetch_kaspa_org_names`, `lookup_online`, `start_label_refresh`.
- `config.rs`: `data_dir()` (`~/.x4kas`), `valid_networks()`, and `ConnectionSettings`/`ConnectionKind`, the last connection choice (`~/.x4kas/connection.toml`).
- `analytics.rs` / `analytics_streaming.rs`: chain analytics (`summarize_chain_blocks` turns VSPC v2 responses into per-chain-block `Metrics`, incl. miners from coinbases; rolled into 1m/10m buckets; `AggregatedView` per window; `TxHistogram`: tx counts per 10m bucket over 24h) and the engine as a chain-stream sink (cache at `~/.x4kas/analytics_cache.bin`, versioned by `CACHE_MAGIC`; bump it when the format changes). The stream (`chain_stream.rs`) starts from the saved position or the pruning point, first skipping ahead (hash-only VSPC v1 batches, `Seeking` phase) to the backfill window; if the node has pruned past the position ("…retention root…" error), it starts over from the pruning point. It reports its progress in `app.analytics.status` (`AnalyticsStatus`/`AnalyticsPhase`), waits for a connected, synced node, and retries failed requests instead of exiting. All chain data comes from the connected node.
- `tx_inspect.rs`: per-transaction classification, mirroring Kaspalytics: protocol detection, output script classes, covenant/introspection/ZK opcode scanning, coinbase node-version parsing.
- `emission.rs`: the block reward schedule ported from rusty-kaspa (subsidy-by-month table, Crescendo DAA scores for mainnet and testnet-10): current reward and next reduction (`NodeState::block_reward`). Also the burn address per network (`burn_address`), polled as `NodeState::burn_balance`.
- `format.rs`: pure formatting helpers shared by GUI and CLI (`format_number`, `format_kas`, `sompi_to_kas`, `format_hashrate`, `format_usd`, `format_duration`, `format_utc`, explorer URLs, `now_ms`). Show KAS amounts with `format_kas`.
- `rpc/client.rs`: `RpcManager`. Connect (`connect` retries forever for the GUI; `connect_once` fails fast for the CLI), background polling (incl. the sink and pruning point headers), the `BlockAdded` stream that feeds the DAG visualizer (`stream_blocks`, joined with polling in the `handles.node` task, resubscribing on every connect), the `UtxosChanged` stream for the watchlist (`watch_utxos`), address balances and pending mempool activity, RPC execution (`rpc_json` returns the full response; `execute_rpc_call` truncates it for the GUI and is also used for Block Info's `get_block`), hashrate estimate, VSPC v2 fetches (and hash-only v1 batches for skipping ahead).
- `rpc/market.rs`: CoinGecko market polling (every 60s).
- `rpc/methods.rs`: `RPC_METHODS` catalog (name, description, typed params with defaults), `resolve_args`, and argument parsers.
- `rpc/hash_links.rs`: finds block hashes (by field name) in JSON responses so the result viewer can link them to `get_block`.
- `rpc/types.rs`: UI-friendly structs with `From` impls for kaspa RPC types.

**x4kas-cli**

- `main.rs`: `#[tokio::main]` entry point. Global clap args (`--url`, `--network`, `--timeout`, usable before or after the subcommand) and the `Command` enum, one variant per command group.
- `rpc.rs`: `x4kas-cli rpc <method> [args…]`. `RpcCall` implements clap's `Subcommand` by hand, generating one subcommand per `RPC_METHODS` entry (positional args; a trailing list takes several words), so the CLI and RPC Cmds tab never drift. `run` validates args (`RpcMethod::validate_args`), connects (`RpcManager::connect_once`; resolver attempts retry until `--timeout`, since it sometimes hands out a dead node), and prints `rpc_json` untruncated.
- `address.rs`: `x4kas-cli address profile|txs|peers|cluster|flows|tx|balance`, reading the index on disk (no node); `txs` and `flows` take `--format json|csv` (`txs --all` for every row, `flows --collapse` to fold chains). `index.rs`: `index status` and the headless `index run` (connects, streams into the index until Ctrl+C, progress on stderr). `watch.rs`: `watch [addr…]`, JSON lines of events and alerts. `labels.rs`: `labels get|list|set|rm|refresh|online|key|kns`.

### Dependencies

- `eframe` / `egui_extras` 0.33. Upgrade them in lockstep; import egui as `eframe::egui`.
- `fjall` 3 for the address index (pure Rust, so the CLI builds without a C++ toolchain). `kaspa-addresses` is a core dependency (address versions for the clustering guard, synthetic addresses in tests); `tempfile` is a dev-dependency (temporary stores).
- Kaspa crates (`kaspa-rpc-core`, `kaspa-wrpc-client`) pinned to git rev `01b532e` (rusty-kaspa v2.1.0). Bump all of them together.
- `reqwest` for CoinGecko.
- `egui_term` (terminal widget on `alacritty_terminal`) is vendored in `vendor/egui_term` (excluded from the workspace, so not formatted or linted) from upstream rev `9a631ca`, the last egui 0.33 revision. Local patches are marked `x4kas:`: keyboard input needs focus only (upstream also required the pointer over the widget), Tab/arrows/Esc are focus-locked to the shell, and a closed event channel no longer panics. Re-vendor when upgrading egui.
- Rust edition 2024. Let-chains are fine, and clippy prefers them over nested `if let`.

## Conventions

- Run `cargo fmt --all`, `cargo clippy --all-targets -- -D warnings` and `cargo test` after changes. Tests cover app state, config, types, formatting, analytics and CLI parsing. GUI code is not unit-tested.
- Shared dependency versions live in the root `[workspace.dependencies]`; crates use `dep.workspace = true`.
- Keep async and RPC work out of `gui/`. Add a `UiCommand` and handle it in the controller instead.
- GUI and CLI share core code. Don't put data fetching or computation in either frontend crate.
- Background code that mutates `App` must call `app.mark_dirty()` so the GUI repaints.
- GUI-only view state (popups open, help or Settings visible) lives in `GuiApp` or egui memory, not `App`, unless tests need it.
- All RPC types have UI-friendly wrapper structs in `rpc/types.rs`. Don't use raw kaspa types in UI code.
- Show every Kaspa address with `widgets::address` and every block hash with `widgets::block_hash`, never a plain label. A block hash click calls `widgets::request_block`; the frame loop in `gui/mod.rs` sends `LookupBlock` and draws the Block Info window (`blockdag::block_window`: hash, explorer links, and the `get_block` JSON whose block hashes link onward) on any tab. Likewise an address click calls `widgets::request_address`; the frame loop sends `LookupAddress` and draws the Address Info window (`address::AddressWindowUi`) on any tab. An address's right-click menu adds, edits or removes the user's label and opens the address in an explorer, and its label chip edits it in place (Enter saves, Esc cancels); label changes go through `widgets::request_label` and `SetLabel`.
- The index store is synchronous and single-writer: never open it on the GUI thread or in an async task without `spawn_blocking`; the controller owns the `Arc<IndexStore>` and query tasks borrow it.
- Dashboard cards are skeletons: they always draw every row ("—" via `or_dash` until the data arrives) and list tables keep a fixed-height body (`wide_table`, with a message row while empty), so nothing jumps as data loads. Don't swap a card's contents for a one-line placeholder, except for a lasting state such as "Disabled when using the public resolver".
- Use `theme::*` colors and `widgets::*` helpers for a consistent look; never hard-code `Color32`s in views. Row labels (`field_label`) use `theme::LABEL`; other secondary text uses `.weak()`. All text is already monospace, so don't add `.monospace()`.
- Shortcuts are ignored while a text field or the terminal has focus (`ctx.wants_keyboard_input()`, `TerminalPane::has_focus`), except Ctrl+`.
- Shortcuts: `1`–`4` tabs, Ctrl+Tab / Ctrl+Shift+Tab cycle, `p` pause, Ctrl+` terminal, `?`/F1 help, Esc closes popups.
- 36 read-only RPC methods (listed in `rpc/methods.rs`) are available in the RPC Cmds tab and as `x4kas-cli rpc <method>` (lists are comma-separated). Responses are pretty-printed JSON (`to_json`; wrap bare values in a `json!` object). To add one, add it to `RPC_METHODS` and a match arm in `RpcManager::rpc_json`; a test checks every method has an arm. It then appears in the CLI (`x4kas-cli rpc <method>`) automatically. State-changing calls (`submit_*`, `add_peer`, `ban`/`unban`, `resolve_finality_conflict`, `shutdown`) are intentionally not exposed.
